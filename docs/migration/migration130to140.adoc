= 1.3.0 -> 1.4.0

== reactive-messaging-redisstream-connector

* JSON-B based serialization/deserialization ability to deal with non-string messages.
** `RedisStreamJsonbMessageConverter` — automatically deserializes incoming JSON string payloads to the `@Incoming` method's parameter type.
** `RedisStreamJsonbSerializer` — automatically serializes non-`String` payloads to JSON when using `Emitter<T>` on outgoing channels.
** Custom `Jsonb` instance can be provided via a CDI producer; the default is `JsonbBuilder.create()`.
* New pipelined batch write support for outgoing channels.
** When `RedisStreamMetadata.withPipelined(true)` is set, `Iterable`, `Stream` and object-array payloads are split into multiple Redis stream entries and sent with implementation-specific batch/pipeline support.
** Without this metadata flag, batch-like payloads keep the previous behavior and are sent as a single serialized payload.
* Outgoing retry backoff handling was corrected to use `Duration.ofMillis(retryMaxDelayMs)` for the maximum delay.
** If you use `retry-max-delay-ms`, note that before this fix the maximum retry backoff could be interpreted as seconds instead of milliseconds.

=== Migration

You may need to add a dependency on a JSON-B implementation if you don't already have one.
If you extend `RedisStreamsConnector` and override its protected `xAdd(...)` method, note that its return type changed from `Uni<String>` to `Uni<List<String>>` to support pipelined batch writes. Custom subclasses overriding that method must be updated accordingly.
